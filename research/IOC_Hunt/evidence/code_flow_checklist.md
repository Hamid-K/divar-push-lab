# Code-flow check for a YARA hit

The known Divar path was reconstructed from signed APKs spanning 2023–26. Use this checklist when a DEX rule fires. A string or opcode hit alone cannot establish the chain.

1. **Identify the APK.** Record the exact APK SHA-256, package, versionCode, distribution variant and signer. Locate the DEX member that defines the candidate worker; other parts of the route may live in different DEX members of the same APK.
2. **Find an ingress.** The known push routes enter through Divar's OneSignal extender or direct FCM data handling. A matching title equals `push_id`; body JSON has nonempty `callback_url` and `action`. Later positive builds also require `campaign`. The qualifying branch creates an explicit broadcast before normal notification display. In sampled 11.8.1–11.9.3 positives, the relayed URI is the plain `callback_url`. In sampled 11.9.6–11.13.11 positives, the relayed URI is `campaign`; `callback_url` remains a gate. Recompiled code may implement equivalent logic differently.
3. **Check the receiver.** The known receiver validates `Intent.dataString` against an extra whose key and value are that same string, then starts `ReportDeserializer` on a thread. An `android:exported=false` manifest entry means this is an internal path, not evidence of an external-app broadcast entry point.
4. **Check the alternate header ingress.** Sampled 2026 builds can read `X-CORRELATION-ID` from an HTTP **response** on a wired API client. The code Base64-decodes it, XORs bytes with decimal 100, splits the result on `&`, and uses the two fields as an explicit receiver class and relayed URI. Confirm the interceptor is attached to a client actually used by the app. The header name alone is not an IoC.
5. **Check the worker.** Sampled 2023–25 encoded workers Base64-decode the relayed `campaign` and XOR bytes with decimal 63 to obtain a URL; sampled 2026 workers use decimal 104. The worker fetches an HTTP response and parses its first line as JSON. The eight relevant keys are `format`, `parse`, `data`, `report`, `objectify`, `deserialize`, `extra` and `local`. It uses reflection to decode bytes, writes a file, invokes a selected method with a `String[]`, waits, and attempts cleanup. Follow the actual method calls rather than assuming the response selected `Runtime.exec` or an Android exploit.
6. **Separate capability from use.** A complete path in a signed APK is a static capability. Confirm an actual sent push or header, targeted recipients, response body, stage bytes and device effects from service/device/network records before asserting deployment or impact.

The sampled sequence is not continuous: known-route-negative releases occur between positive periods and in a beta variant. The [public reference ledger](release_inventory_reference.csv) carries exact versionCode and status for each acquired APK. [Ramin Farajpour Cami's original disclosure](https://gist.github.com/raminfp/a548a2af86108eb40b8bffc5c8f07aaa) supplied the initial lead; this hunt bundle's rule counts were recalibrated against the acquired signed APK corpus on 4 October 2026.
